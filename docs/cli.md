# CLI reference

For procedures and safety checks, see [operations](operations.md), [backup and restore](backup-restore.md), and [Tailscale and ReadKit](tailscale-readkit.md). Select the intended [runtime configuration](configuration.md) before operating on an instance.

## Entrypoints and help

Run commands from the selected checkout after `uv sync --locked`:

```sh
uv run --locked rss --help
uv run --locked rss restore --help
uv run --locked rss-dev --help
```

`rss COMMAND [ARGS]` manages the native runtime. `rss-dev` manages Python tooling, not FreshRSS. `uv run --locked python -m rss_aggregator` is equivalent to `rss`. Both groups and their subcommands accept `--help`, which prints text and exits 0 without running the operation. There are no other project-defined group options. Subcommand options belong after the subcommand.

`./scripts/rss COMMAND [ARGS]` is a supported launcher with `uv` on `PATH`. It forwards all arguments (including `--help`) and exits with the launched command's status. You can also invoke `/path/to/checkout/scripts/rss` from another directory: it passes its own checkout to `uv run --locked --project` so, unless `RSS_STATE_DIR` is set, the checkout containing the wrapper determines the default state directory. Relative environment paths still resolve from the process working directory.

`rss` emits one indented JSON object on successful operations (exit 0). Diagnostics and prompts go to stderr. Guard, configuration and operation failures exit 1 and normally have no result JSON; see the exception for `backup-status --check`. Invalid CLI usage exits 2. Commands may initialize private control state even for inspection. Some errors occur after work has started: a nonzero exit does not establish that no files changed, no archive was published, or forwarding was withdrawn. Use the corresponding status commands and follow the runbooks before retrying. JSON can contain local paths, private hostnames, or aggregate counts; redact before sharing.

## Runtime commands and results

Use `uv run --locked` before each command below. There are no arguments or flags beyond those shown and `--help`.

| Command | Purpose, behavior and result |
| --- | --- |
| `rss setup` | Install the checkout's checksum-pinned Apple Silicon runtime, or verify a matching existing installation. Returns the native ownership receipt (`schema`, `token`, `manifest`, `source_tree_sha256`). Does not start services or install jobs. First-time setup refuses nonempty unowned roots except for a recognized private command lock or a matching first-setup checkpoint and its own published files. Retry an interrupted publication with the same pin; changed or unrelated paths are refused, as are drift and implicit upgrades. |
| `rss start` | Record running intent after the maintenance and owned-runtime checks; start, reopen, or retain a matching backend after rechecking effective web security. A genuinely new local instance allows the upstream installer. An initialization change uses guarded restart; initialized startup checks authentication/SQLite and fetches feeds. Missing previously provisioned data or a missing explicit selection are refused. Startup PHP preparation/configuration has a 120-second deadline per operation; foreground feed fetch has a 600-second deadline. Their deadlines and writer exclusion survive CLI loss; a timeout is reported without PHP output. Refuses a known occupied replacement port before stopping the existing generation, but cannot rule out a later bind race. For private startup, refreshes the forwarding checks after preparation. Reopening a previously private port in local mode still requires its read-only Funnel check, including cold supervised recovery. Invalid private-backend evidence can block startup. Ordinary HTTP is gated until the controller acknowledges approval; startup requires the same live generation and ordinary HTTP readiness before reporting success. Returns `runtime`, `application`, `url`, `instance`, `security`, `scheduler`, `fetch`, and `forwarding` when private; a retained service also includes status fields. `fetch.status` is `installer_pending`, `completed` or `already_running`. |
| `rss status` | Inspect without starting writers. Always reports `runtime` (`installed`/`absent`), `application` (`running`/`stopped`/`unconfirmed`) and `http_ready`. For an installed runtime it includes `instance`, `scheduler` and `forwarding`; `url`, `port` and `live_instance` appear when a live generation is observed. `instance` names the selection, not necessarily the serving instance; `http_ready` requires them to match. An unused state path remains eligible for `setup` after status or a refused `start`, `verify`, or `backup`. A successful status is not a health attestation; check `http_ready`, scheduler and forwarding separately. |
| `rss fetch` | Attempt an immediate upstream fetch on the selected, verified running service, respecting FreshRSS cache, TTL and backoff. JSON `status` is `completed` or `installer_pending`. An overlapping fetch or unready service can be refused. The full fetch has a 600-second deadline; timeout exits 1 without upstream output. Completion is not a count of new articles. |
| `rss verify` | Reopen the live owned service through the startup checks, preserving its observed private/local mode. Requires a running service and interrupts access during the restart; a startup failure, including a fetch timeout, can leave writers stopped. Returns the `start` result plus `verified: true`. On confirmed public exposure of that backend, requests writer shutdown without changing the foreign route and reports confirmation or uncertainty. Not a trusted-client HTTPS check. |
| `rss stop` | Persist explicit stopped intent, withdraw owned forwarding, stop writers and verify a shutdown backup of the identified writer or selected idle instance when data exist. Returns `application: "stopped"`, `already_stopped`, and `backup` (a verified archive result or `{"status":"no_data"}` on a pristine installation). `already_stopped: true` reports prior writer state, not a no-op: a repeated stop can publish another full ZIP. Quiescence is attempted even if stopped intent or shutdown evidence cannot be saved; unavailable selection and capture records or runtime layout cannot block it. A forwarding discovery timeout does not skip writer shutdown or prove forwarding was removed. A damaged standalone fetch lease can still allow closure of an independently identified web controller without proving quiescence for capture. If ownership cannot be established, refuse to touch unidentified writers or forwarding. In established state, the durable receipt-loss shutdown record vetoes automatic restart even if writing stopped intent is interrupted. On failure, inspect `status` and `backup-status`. If the intent write failed, recorded intent can still show `running`; fix the write failure and retry `stop` before reconciling a hold. A maintenance hold may block further work even when stopped intent was recorded. |
| `rss api-check [--loopback]` | Prompt locally for the FreshRSS username and hidden **separate API password**. Default uses the owned trusted HTTPS origin; `--loopback` explicitly tests only the owned `127.0.0.1` backend, without checking TLS. Both require a verified running service. Returns `diagnostics: "PASS"`, `authenticated`, `subscriptions` and `sample_articles` counts, `transport` (`https`/`loopback`) and `https_verified`; never returns credentials, tokens or response bodies. Refuses redirects, untrusted HTTPS, rejected credentials or unusable responses. |
| `rss backup` | Quiesce writers and publish a complete verified archive to the configured destination outside Git and all native state directories. Refuse a mismatch between selection and the serving instance rather than copying or switching the wrong data. Attempt to resume a previously running backend if allowed by intent; republish only the forwarding withdrawn by this backup. Before reopening a previously private backend without republishing, check for public Funnel forwarding; the port retains this check even in local mode or after the controller exits. Failed checks leave writers stopped. Returns `archive` (absolute ZIP path), `sha256` (whole ZIP), `verified`, `manifest`. Publication and resumption can succeed or fail independently; inspect `backup-status` on failure. |
| `rss restore ARCHIVE --instance NAME` | Read an existing native v2 archive into a **fresh** owned instance without selecting or starting it, or interrupting an already running instance. `ARCHIVE` must be an existing file path; `--instance` is required and has no default. Returns `restored: true`, `instance`, `selected: false`, `manifest`, `next_step`. Refuses incompatible runtime metadata, unsafe archives, the selected name and existing targets. |
| `rss select-instance NAME` | Select a complete, compatible owned instance by name (not a path) while all writers are stopped and maintenance is clear. Returns `instance`, `selected: true`, `next_step`; starting is separate. A later enabled supervisor may honor retained running intent; explicitly stop before changing selection. |

Use lowercase names of up to 48 characters for recovery targets: start with a letter or digit, then use letters, digits or hyphens. `default` is initially selected; choose a different fresh name when recovering. If an explicit selection is lost, reselect the intended compatible instance while stopped; startup and backup will not fall back to `default`. See [backup and restore](backup-restore.md) before using an archive. The `scheduler` result reports `running`, `cron` (`*/20 * * * *`), `timezone` (`UTC`) and `last_fetch` (last periodic result for this generation: `completed`, `failed`, or null). An independent caretaker enforces each scheduled fetch's 600-second deadline and reaps the PHP writer even if the controller exits. A surviving controller records a timeout as `failed` and can run later eligible slots. An `unconfirmed` service is not proof of idle writers; see [operations](operations.md#backups-and-stopping). `security` reports the effective web `sapi`, `php`, `upload_progress`, `expose_php`, `display_errors`, `sqlite`, `loaded_ini`, `scanned_ini`, `initialized`, `authenticated_settings`, and `verified`; it is not just CLI PHP metadata. `forwarding.status` is `unconfigured`, `stopped` or `running`, with a `url` for a recorded route. It is not end-to-end client verification.

### Preview-first runtime changes

| Command | Preview and apply |
| --- | --- |
| `rss upgrade [--confirm TOKEN]` | Explicitly change to this checkout's reviewed PHP/web runtime pin for the **same FreshRSS source and platform**. If instances exist, apply requires the selected instance's verified shutdown archive covering its last writer generation, revalidated against the installed pin. Relevant unresolved shutdown or ambiguous writer evidence blocks apply. Stages and verifies replacement before publishing; does not start FreshRSS. Matching pins need no replacement. Returns `status: "installed"` and `manifest`. This does not migrate FreshRSS versions or make earlier archives compatible with a different runtime. |
| `rss uninstall [--confirm TOKEN]` | Remove only the verified owned runtime, retaining instance data, ownership and archives. Does not remove global packages, Tailscale or a legacy VM. Returns `status: "uninstalled"` and `preserves_data_and_archives: true`. |

Both require stopped writers and no running intent, no supervision or daily backup registration, and no active or uncertain owned forwarding. Both preview and apply check role-specific plist paths and read-only job queries in the normal GUI session; absent ledgers alone do not prove the jobs are retired. An unavailable session, ambiguous query or leftover job definition refuses the change without adopting or deleting it. Resolve maintenance first, verify a backup and follow [operations](operations.md#safe-cleanup). Omit `--confirm` for the preview (`status: "preview"`, `operation`, `runtime_path`, `installed`, `preserves_data_and_archives`, `confirmation`, plus `reviewed_manifest` for upgrade). To apply, rerun the same command with `--confirm` and the exact SHA-256 token from the current preview. An incorrect or stale token refuses without applying. Preview is not authorization to delete data or repair ownership records.

### One-time migration command

`rss import-legacy ARCHIVE --instance NAME` is intentionally hidden from group help; its own `--help` works. Its arguments and non-activation behavior match `restore`; its success result adds `imported: true`. It accepts only the reviewed legacy v1 image identity at the same FreshRSS release, validates the full payload and publishes a fresh private native instance. It never operates on the legacy VM. This is **not** ongoing legacy restore support or a reverse importer; follow the [one-time migration handoff](operations.md#one-time-migration-from-podman).

`replace`, `select-volume`, `remove-vm`, `delete-volume`, and `remove-package` are not native commands. The [legacy CLI and guarded removal documentation](https://github.com/brucepucci/rss-aggregator/blob/28664ab936f8872da6ff3ddca1c4b0a725dfb0ec/docs/cli.md#cleanup-commands) stay with their own revision and deployment.

### Mac supervision commands

| Command | Purpose and result |
| --- | --- |
| `rss supervision-install` | Explicitly register/activate the owned normal-user GUI-session job, capturing this checkout and its settings. Returns supervision status; does not set running intent. Refuses a missing session, foreign/changed definitions, changed capture, or settings that disagree with the running listener's port or access mode. |
| `rss supervision-remove` | Unload and remove only unchanged owned supervision; preserve intent, service and data. Returns supervision status; refuses foreign/changed jobs. |
| `rss supervision-status` | Report registration, intent, session and observed health without starting or restarting writers. Unavailable and unhealthy results are successful queries, not recovery successes. Invalid control records and lock failures exit 1. |
| `rss supervision-tick` | Run one serialized supervision cycle from the selected state. Disabled, intentionally stopped or unset intent are no-ops; a healthy observation resets the retry budget without restarting. At most three consecutive guarded attempts, with 60 and 300 seconds between attempts. Maintenance, a pending stop veto, live endpoint conflict, inactive/unavailable registration, backoff, failed or exhausted recovery and lock failures exit 1 without result JSON; inspect status for the next action. |

Supervision results include `enabled`, `state`, `intent` (`unset`, `running`, `stopped`), `maintenance`, `session` (`not_checked`, `available`, `unavailable`), `observed`, `recovery`, and `action`. Registered jobs add absolute `job`, `root`, and `state_dir`. **`enabled: true` means the registration ledger exists**, not that launchd loaded the job, the session is available, or the service is healthy. A bootstrap failure can leave the ledger in place.

`state` is `disabled`, `maintenance`, `stop_requested`, `configuration_unavailable`, `session_unavailable`, `inactive`, `intentionally_stopped`, `intent_unset`, `configuration_conflict`, `healthy`, `unhealthy`, `recovery_failed`, or `retry_exhausted`. A successful recovery tick returns `recovered`. `observed.availability` is `unknown`, `healthy`, `unhealthy`, or `configuration_conflict`; an available observation can include `runtime` and `application`, and a conflict or error can include a sanitized `reason` and `action`. A live endpoint conflict does not restart the service or spend a retry. `stop_requested` means durable shutdown evidence revoked automatic restart before stopped intent was confirmed; recorded `intent` can still be `running`. Retry `stop` to confirm the shutdown, or use deliberate `start` to supersede the veto without clearing shutdown failure evidence.

`recovery` includes `version: 1`, `attempts` (0–3), `next_retry_at` (UTC Unix seconds or null when no retry time is scheduled), and `history` (up to ten recent events). An event records UTC Unix `at`, `attempt`, and `outcome` (`interrupted_or_in_progress`, `failed`, or `recovered`). Failed events can include a sanitized `reason` and `action`; reasons include `ownership_conflict`, `configuration_conflict`, `private_access_refused`, `security_gate_failed`, `readiness_failed`, `fetching_unhealthy`, `external_command_failed`, and `recovery_guard_failed`. Reserving an attempt before recovery makes an interrupted attempt count against the retry budget. Explicit `start` and healthy ticks reset the budget without discarding history.

Use [captured configuration](configuration.md#captured-mac-supervision-configuration) and [operations](operations.md) to change job settings. Daily backup is independent.

### Daily backup commands and results

| Command | Purpose and result |
| --- | --- |
| `rss backup-enable [--hour HOUR] [--minute MINUTE]` | Explicitly install/activate the owned user-session daily backup job with a private backup destination. UTC hour `0–23` (default `3`), minute `0–59` (default `0`). Result includes `enabled`, `job`, `daily_utc`, `next_expected_attempt`. Activation is not evidence of protection; changed captures require explicit disable/re-enable. Damaged daily evidence must be inspected before enabling. |
| `rss backup-disable` | Remove only the owned daily job; keep evidence and archives. A missing plist is recoverable with a valid ledger and matching live identity if loaded. Returns `enabled: false` and, on removal, `archives_preserved: true`. Exits 1 for a foreign/changed job or if valid daily evidence conflicts with the current registration policy; in the latter case even an unchanged owned job stays registered. Preserve both records, inspect `backup-status`, and do not proceed with a change requiring job retirement. |
| `rss backup-due` | Run only eligible daily work for the configured job. `outcome` is `disabled`, `not_due` (with `next_expected_attempt`) or `success` (with `backup`). Guard, contention or capture/resumption failures can exit 1; inspect `backup-status`. Contention is recorded as a defer only for an established, registered owned schedule; contention during first setup does not record a defer. Invalid daily evidence (including missing target identity) is preserved and blocks an attempt. Each instance and registration retains its slot and retry budget across reselection and backward UTC changes. Not a force-backup command; use `backup` for a manual capture. |
| `rss backup-reconcile` | Release an interrupted maintenance hold only after checking its ownership receipt and confirming idle writers and no active owned forwarding. Does not need the installed runtime files or clear failed shutdown evidence. Returns `reconciled`, `resumed: false`, `action`. Does not start writers or change intent. Refuses unknown holds and unconfirmed writers/forwarding; an explicit-stop hold, a later stop recorded against a backup hold, or a recorded stop veto also requires persisted stopped intent. |
| `rss backup-status [--check]` | Report daily protection and backup/maintenance evidence without starting writers. Default exits 0 for a report even if unprotected. `--check` emits the same JSON then exits 1 with a stderr diagnostic unless `protected` is true. |

### Daily backup status results

- `enabled`, `registered`, `registered_at`, `registration_id`, `scheduler_problem`, and `next_expected_attempt` describe the captured schedule and session registration, not a successful backup. `registered_at` and `registration_id` are null without a completed registration. An identical disable/re-enable starts a new registration. `busy` means the operation lock is held; status can still report recorded evidence. Runtime layout drift or missing/changed managed writer leases mark protection unhealthy without hiding readable attempt or archive records. A serving writer's valid held lease is not itself a fault.
- `daily_attempt` is the last recorded daily attempt across targets, or null. `daily_target_attempt` has the same fields for the selected instance in the current registration, or null. Each includes UTC `slot` and `attempted_at`, `count` (1–3), `outcome` (`running`, `success`, `failed`, or `interrupted`), `instance`, `policy_id`, `registration_id` and, on success, `archive` and `sha256`. A `daily_due` slot is eligible and incomplete; clock rollback does not reopen an earlier slot. `missed` flags an unattempted slot more than 15 minutes past its target. `next_expected_attempt` accounts for retry delay and exhausted budgets. Without an active command, an unfinished daily reservation is shown as `interrupted` in both views without rewriting the record or refunding an attempt. `latest_defer` records contention separately. `daily_archive_available` checks the selected registration's archive, not a different target's publication.
- `latest_attempt` is null when no readable attempt is recorded, otherwise an object with UTC `started_at`, `kind` (`backup` or `stop`), `outcome` (`running`, `success`, `failed`, `interrupted`, or `no_data`), and `instance` (name or null; may be omitted on a scheduler preflight refusal). It can include `resumption` and an `action` for failure or interruption. A recorded `running` attempt with no active command is reported as `interrupted`.
- `latest_success` is null when there is no readable verified publication, otherwise an object with absolute `archive`, whole-ZIP `sha256`, `verified: true`, archive `manifest`, UTC `completed_at`, `instance`, `writer_generation` (generation ID or null), and `via` (`backup` or `stop`). It can refer to a publication before a newer failed attempt, or to a publication whose resumption failed. A damaged evidence record is named in `evidence_problems` without hiding other readable evidence.
- `resumption` describes the attempt's reported outcome, not the current hold. `preserved` covers a preflight refusal, successful resumption, or intentionally leaving the service stopped; it does **not** prove a restart or a restored private route. `failed` records failed restart after quiescence and can persist after reconciliation clears the hold. `unresolved` means no confirmed result was available for the held attempt. `not_resumed` records reconciliation without a restart. `not_attempted` is the default without a recorded attempt and can coexist with a hold. Use `maintenance_required` to check for a hold now, `rss status` for current HTTP readiness, scheduler and forwarding, and the [private-access checks](tailscale-readkit.md) for client availability.
- `age_seconds`, `overdue` and `archive_available` describe the last known archive (no success or age over 26 hours is overdue). `archive_problems` reports filesystem inspection errors for `latest_success` and for the selected daily capture (`daily_target_attempt`, or `daily_attempt` when the two attempts are the same). Status checks whether it can open a regular file for reading; the scheduled check rejects a final symlink. Unavailable archives do not hide readable records. This does not revalidate archive bytes or prove independent recovery.
- `unresolved_shutdowns` lists outstanding shutdowns, most recently recorded first. Each has `instance` (null when unidentified), optional `writer_generation` (null when known to have no generation), `started_at`, `outcome` (`running`, `failed`, `interrupted`) and `action`. `unresolved_shutdown` is the first entry or null. A shutdown of another instance, reconciliation, or manual/daily backup does not clear that failure. Retry `stop` for a verified shutdown archive of the affected instance. No supported in-place command attributes or retires an unidentified failure; see [owner-reviewed recovery](backup-restore.md#consistency-and-failure-behavior).
- `maintenance_required` indicates a hold; inspect and reconcile rather than removing the record. `protected` is the combined local daily health signal for the selected instance, requiring a matching healthy registration, its available recent scheduled archive, and no busy command, outstanding work, failed latest attempt, any outstanding shutdown, evidence or archive inspection problems, or maintenance. It is not Time Machine evidence.

## Developer commands and results

Each command has syntax `uv run --locked rss-dev COMMAND [--project DIRECTORY] [--help]`. There are no positional arguments. Optional `--project DIRECTORY` belongs after the subcommand and defaults to the current working directory; relative paths resolve from there. Select a synchronized project directory (the Git repository root for `setup`). Files are usage errors.

| Command | Purpose, defaults and result |
| --- | --- |
| `rss-dev check [--project DIRECTORY]` | Complete non-live pytest, Ruff lint and Ruff format checks. All three run even after an earlier failure. JSON `checks` names: `pytest`, `lint`, `format`. No source fixes. |
| `rss-dev setup [--project DIRECTORY]` | Inspect Git and activate pre-push hooks safely; returns `ok`, `active`, and for no-remote/manual-resolution cases `reason`, `next_step`. No remote: success with `active: false`; rerun after adding one. Refuses foreign/legacy/nonexecutable arrangements without changing them, and preserves recognized executable hooks. See [managed hooks](development.md#managed-pre-push-hooks). |
| `rss-dev format [--project DIRECTORY]` | Rewrite Python formatting with Ruff; no lint fixes. JSON `checks` name: `format`. |
| `rss-dev fix [--project DIRECTORY]` | Apply only safe Ruff lint fixes; no formatting or unsafe fixes. JSON `checks` name: `fix`. |

`check`, `format`, and `fix` emit `{"ok": true, "checks": [{"name": "pytest", "returncode": 0}, ...]}`, with entries appropriate to the command. `ok` is true when every child succeeded; OS-level launch failures are recorded as return code 127. Logical failures still emit JSON with `ok: false` and exit 1. Child output goes to stderr. Invalid CLI usage exits 2; help exits 0. Commands use the selected checkout's local `.venv` and isolated child environment, not the caller's editable installation or a shared environment. They do not create/synchronize environments or start FreshRSS. See [selected-checkout isolation](development.md#selected-checkout-isolation).

## Pytest selection

`uv run --locked pytest [OPTIONS] [file_or_dir ...]` prints normal pytest reports, not CLI JSON. No path selects `tests/`; paths/node IDs narrow direct runs, not the full baseline. The default marker expression is `not live`. Select the native integration explicitly with `uv run --locked pytest -m live tests/integration/test_native.py` after reading the [platform prerequisites and limits](development.md#explicit-liveplatform-checks).

`-m EXPRESSION` selects markers; `-s` disables capture; `-p no:cacheprovider` disables the cache plugin; `-q`/`--quiet` reduces verbosity; `--tb=short` shortens tracebacks; `-h`/`--help` prints upstream help. `rss-dev check` is the guarded baseline; direct runs retain normal pytest environment handling. Pytest exits 0 on success, 1 for test failure, 2 for interruption/collection errors, 3 for internal errors, 4 for usage errors, and 5 for no tests collected. `RSS_LIVE`, `RSS_OBSERVE_CRON`, `--observe-cron` and old unittest paths are unsupported here. Do not publish `--showlocals` output.

## uv setup and dependency commands

These upstream commands produce uv text/progress rather than project JSON. Resolution, environment and build failures exit nonzero before a project command runs.

| Command or option | Purpose |
| --- | --- |
| `uv sync --locked [--project DIRECTORY]` | Synchronize the selected checkout's `.venv` with the lock and default development group. May download Python/packages/build tools; refuses stale or missing lock requiring changes. No hooks or FreshRSS startup. |
| `uv run --locked EXECUTABLE [ARGS ...]` | Use the project environment, syncing if needed without changing the lock. Options after the executable go to that executable. Propagates its exit status. |
| `--offline` (uv option) | Use cached resources only; missing caches fail. Does not block network access by a command such as native setup or selected integration. Used by the pre-push gate. |
| `uv lock` | Intentionally regenerate `uv.lock` after reviewed changes; follow with locked sync and baseline checks. |
| `uv sync --help`, `uv run --help`, `uv lock --help` | Upstream help for additional options; no operation is performed. |
